# یسرا | نسخهٔ وب (داشبورد)

**تبدیل اپلیکیشن اندروید [یسرا](https://github.com/heydarsaki-dev/Yosra) به یک داشبورد وب مدرن، تمیز و رنگارنگ** — ساخته‌شده با **Next.js ۱۶**، **Tailwind CSS v4** و **TypeScript**.

همهٔ امکانات اپلیکیشن اندروید (فارسی و راست‌چین) در قالب یک وب‌اپلیکیشن responsive با چارت‌های جذاب پیاده‌سازی شده است.

---

## ✨ امکانات

### 🌗 تم تاریک / روشن
- **دارک مود** با پالت نیلی عمیق و رنگ‌های نئونی — با دکمهٔ ☀️/🌙 در تاپ‌بار سوییچ می‌شود
- انتخاب کاربر در `localStorage` ذخیره و در اجرای بعدی اعمال می‌شود
- اگر انتخابی نباشد، از **الویت سیستم** (`prefers-color-scheme`) پیروی می‌کند
- بدون پرش رنگ (FOUC) — با اسکریپت پیش‌هیدرات
- همهٔ چارت‌ها و تولتیپ‌ها هماهنگ با تم هستند

### 📱 ریسپانسیو کامل (موبایل)
- همهٔ صفحات در ۳۹۰px و بالاتر بدون اسکرول افقی و بدون سرریز هستند
- ناوبری پایین فریم در موبایل، سایدبار در دسکتاپ
- دکمه‌های اکشن، کارت‌ها و نمودارها به‌صورت اختصاصی برای صفحات کوچک بهینه شده‌اند

### 🏠 داشبورد (صفحهٔ اصلی)
- کارت گرادیانی **موجودی کل** + درآمد و خرج ماه جاری
- کارت **امروز**: درآمد و خرج امروز + نمودار **اسپارک‌لاین عریض** روند ۷ روز اخیر
- کارت **بدهی و اقساط**: قسط‌های سررسید این ماه، باقی‌مانده و پرداخت‌شده، نوار پیشرفت و دکمهٔ مدیریت
- **آخرین تراکنش‌ها** با امکان جابجایی (مرتب‌سازی دستی)
- **نمودار میله‌ای ۷ روز اخیر** (درآمد سبز / خرج قرمز، با تولتیپ)
- **دونات ترکیب ماه** + **بیشترین‌ها** + **به تفکیک کاربر** — هر سه با **سوییچ درآمد/خرج** ✨
- **درآمد همیشه اول** — در همهٔ فرم‌ها و گزارش‌ها تب درآمد قبل از خرج است

### 💸 تراکنش‌ها
- جست‌وجو در یادداشت / دسته / کاربر
- فیلتر همه / درآمد / خرج
- ویرایش و حذف هر تراکنش
- جابجایی دستی ترتیب تراکنش‌ها
- شمارش و مجموع نتایج فیلترشده

### ➕ ثبت و ویرایش تراکنش
- انتخاب نوع (**درآمد اول**)، **قیمت‌نویسی فارسی با جداکنندهٔ هزارگان** هنگام تایپ
- انتخاب کاربر و دسته‌بندی به‌صورت چیپ
- **تقویم شمسی سفارشی** (کاملاً فارسی، با روز جاری)
- انتخاب ساعت و دقیقه
- یادداشت و **بررسی موجودی** هنگام ثبت خرج

### 📊 گزارش‌ها
- حالت **روز / ماه** با ناوبری دوره‌ای
- کارت‌های KPI: درآمد دوره، خرج دوره، سود خالص، تعداد تراکنش
- **نمودار میله‌ای روزانه** برای ماه جاری
- **دونات به تفکیک دسته** با سوییچ **درآمد (پیش‌فرض) / خرج** و درصد
- **به تفکیک کاربر** با نوار پیشرفت و سوییچ درآمد/خرج
- لیست تراکنش‌های روز انتخاب‌شده

### 💳 بدهی و اقساط
- افزودن/ویرایش/حذف طلبکار با **پیش‌نمایش تعداد قسط**
- صفحهٔ جزئیات هر بدهی با **برنامهٔ کامل قسط‌ها (شمسی)**
- ثبت پرداخت هر قسط → یک تراکنش خرج خودکار ساخته می‌شود (با دستهٔ «بدهی»)
- لغو پرداخت → تراکنش مربوطه حذف می‌شود
- نوار پیشرفت بازپرداخت و کنترل موجودی

### ⚙️ تنظیمات
- **مدیریت کاربران**: افزودن/ویرایش/حذف با انتخاب ایموجی و رنگ آواتار
- **مدیریت دسته‌بندی‌ها**: دسته‌های درآمد/خرج با جابجایی ترتیب
- **پشتیبان‌گیری محلی**: خروجی/ورودی فایل JSON
- **همگام‌سازی خودکار با گیت‌هاب**: فقط با وارد کردن **رمز**، اتصال برقرار می‌شود و:
  - هر تغییری در وب به‌صورت خودکار در ریپوی خصوصی `yosra-backup` آپلود می‌شود
  - هر ۶۰ ثانیه و با بازگشت به تب، نسخهٔ آنلاین بررسی و دریافت می‌شود
  - فایل پشتیبان به‌صورت **همان فرمت SQLite اپلیکیشن اندروید** (`yosra.db`) ذخیره می‌شود —
    بنابراین اپ اندروید و وب از یک دیتابیس مشترک استفاده می‌کنند و داده‌ها همیشه یکسان‌اند
- بازنشانی داده‌های نمونه / پاک‌کردن کامل داده‌ها

## 🚀 اجرا

```bash
npm install
npm run dev      # محیط توسعه: http://localhost:3000
npm run build    # نسخهٔ producción
npm run start    # اجرای نسخهٔ build شده
```

> هیچ سرور یا دیتابیسی لازم نیست؛ همهٔ داده‌ها در `localStorage` مرورگر ذخیره می‌شوند.
> در اولین اجرا، داده‌های نمونه (درآمد/خرج/بدهی تستی) ساخته می‌شود تا چارت‌ها پر به‌نظر برسند؛ از تنظیمات قابل پاک‌کردن است.

## 🔐 نحوهٔ همگام‌سازی

دقیقاً همان منطق `Sync.kt` در اپلیکیشن اندروید پورت شده است:

1. **توکن به‌صورت رمزنگاری‌شده** در سورس قرار دارد (`vault.ts`) — با الگوریتم
   `PBKDF2-HMAC-SHA1` (۲۰۰۰۰ تکرار + salt) و XOR محافظت می‌شود.
2. کاربر فقط **رمز** خود را وارد می‌کند → توکن در حافظهٔ مرورگر باز و ذخیره می‌شود.
   رمز اشتباه به سادگی رد می‌شود (توکن با پیشوند `ghp_` شروع نمی‌شود).
3. دیتابیس به‌صورت **فایل خام SQLite** (`yosra.db`) در ریپوی خصوصی `yosra-backup` ذخیره می‌شود —
   دقیقاً همان فایلی که اپلیکیشن اندروید می‌خواند. جداول اقساط (`installments`, `inst_paid`)
   در سینک دوطرفه حفظ می‌شوند تا داده‌های کاربر از بین نروند.

| موقعیت | رفتار |
| --- | --- |
| اولین اتصال | اگر روی گیت‌هاب نسخه‌ای باشد → دریافت می‌شود؛ در غیر این صورت داده‌های محلی آپلود می‌شوند |
| تغییر در وب | آپلود خودکار (با تأخیر ۳ ثانیه) |
| هر ۶۰ ثانیه / فوکوس تب | بررسی نسخهٔ آنلاین → دریافت اگر جدیدتر باشد |
| تغییر آپلودنشده | آپلود بر دریافت ارجحیت دارد (تطابق رفتار اندروید) |
